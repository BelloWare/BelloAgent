## 0.1.131

Owner, 2026-10-22: "once you release the current version, please check this and try to replicate this and actually fix this."

- [ ] SCROLL-1: opening a long chat shows a turn's tool calls grouped ("42 calls") when the whole turn is loaded but as detailed rows when the loaded window starts inside it, and scrolling through a long chat loads too little at a time. Grouping must not depend on how much is loaded; the owner suggests loading far more rows at once (about 1,000).
- [x] EDIT-1: editing an earlier message can take very long to start even when the message is on screen. Cause: Edit put the message in the composer only after reading its complete original, and for a chat the helper opened from its metadata file that read replays the whole journal (3.9 s in a 103 MB chat, on the first edit after the helper opened the chat); typing meanwhile dropped the edit. Fixed (a131-edit): the question on screen goes into the composer at once (12–23 ms in Release, 103 MB and 259 MB chats), under its banner and ready for typing; its images, skills and Send's checks are read behind it, Send waits for them, typing stays, and a restart in between reads them again (docs/validation/a131-edit-0.1.131.md). Owner decision 2026-10-23, "Re-check at Send", done: Send checks an edit against the conversation through the edited message (`editSourcePrefix`), so an edit opened during a run is sent after the run added rows, and a changed message or earlier conversation is still refused. Review fixes: Edit again after a failed read keeps what was typed, and a skill chosen while the original loads keeps its arguments.
- [ ] PERF-1 (0.1.130 soak): beside the floating Agents, Diff and Files card a newly shown reply's text is laid out at the 840 pt page width, then again at the narrower column; the card's own refresh and drawing add about 0.5 s per two minutes of chat switching. Lay a reply out once at its real width and cut the card's repeated work.

**All work goes on `dev/next`.** Workstream branches (`dev/appkit-*`) are merged here by the integrator. `main` holds released versions only — never push to `main` outside a release.

## How work is done
- Parallel workstream agents, each in its own worktree, build folder and Codex session (gpt-6.1-sol, xhigh, read-only) that plans every step and reviews every diff before commit.
- Port, don't redesign: same layout, spacing, colours, motion, copy and behaviour. Compare gallery captures before and after (`scripts/compare-captures.py`); differences must be run-to-run data only.
- Performance discipline: reuse views, draw only what is visible, never relayout what didn't change, no work per token across the window. Measure against the baseline below.
- Existing tests keep passing; tests that read SwiftUI structure are rewritten to read AppKit/accessibility instead, never deleted without an equivalent.
- Checks: `scripts/check-next.sh` (build, `test <Class>…`, `helper`, `gate`). Serial-lane classes run alone.

## Rules for code on this branch
- AppKit only for new code. A file stops importing SwiftUI when its port is done.
- Keep the app's Pi look; no stock-looking controls.
- Keep `packages/bello-views` free of app types; macOS 13. App target macOS 14.
- Motion policy unchanged. Accessibility (A1) must not regress: native AppKit accessibility roles, labels, values and selected states.
- Tick items here in the commit that finishes them.
