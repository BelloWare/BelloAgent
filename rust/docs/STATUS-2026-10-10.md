## CI state and repairs

Before this checkpoint `b6e0e31d`, `b50a00fd` and `48de4803` each failed both
workflows (last green: `4bde7489`). Docs-only commits after `48de4803` do not run
CI. Both causes are environmental test-fixture problems, not product defects:

- **macOS** (`cargo test -p bello-agent-core`, reproduced locally: 6 of 725 failed).
  The six `sidebar_search::cache` tests built their source fixture with a plain
  `tempfile::tempdir()`. macOS reaches `$TMPDIR` through the `/var` →
  `/private/var` symlink, and observed sources deliberately refuse aliased
  ancestors (`Unsafe observed source ancestor`). The fixture now uses the
  canonical temporary root, as `unloaded_tests.rs` already did. The product rule
  is unchanged; production data lives under canonical Application Support.
- **Linux** (*Prepare private synthetic fixture parent*). The script created the
  fixture under `/opt`, but GitHub's Ubuntu image runs `chmod -R 777 /opt`
  (`actions/runner-images`, `images/ubuntu/scripts/build/configure-system.sh`),
  which the script's own ancestor policy rejects. It now creates a dedicated
  root-owned `0755` parent `/bello-agent-ci` (exclusively, or validates an
  existing one) and removes it when empty after cleanup. Failures of this step are
  repeated as an `::error::` annotation, which the public check-runs API exposes
  without log access.

A local replay of every `rust-macos.yml` step on this Mac (macOS 14.8, Rust 1.99.0,
Xcode 16.1) is recorded in the commit message. Exact-commit CI is authoritative
for macOS 26 and Linux. Both workflows passed on `7ece0f96`, `36a9fbb5` and
`52c9d82e`.

## What an ordinary user gets today

A release build with default features (`cargo build --release -p bello-agent-app`)
launches to a disconnected single-project workspace. To chat, the user must start
it from a terminal with `--profile FILE --credential-stdin`; the key is held in
memory only. There is no in-app connection setup, no saved credentials, and **no
model tools** (no read/write/edit/bash/MCP/skills). The synthetic tool, MCP,
skills and Connections workflows are compiled only with
`all(feature = "synthetic-authority", debug_assertions)`, i.e. never in a release
binary. The `native-authority` feature adds Rust-vault Connections and saved
provider chats behind `--native-authority`, but requires an approved signed
identity that has not been produced, and still offers no tools.

## Performance on this Mac (release builds, shipped Swift 0.1.122)

Full method, raw trials and harness: [validation/swift-rust-performance-2026-10-10](validation/swift-rust-performance-2026-10-10/README.md).
The Mac is an Apple M3 Max virtual machine (60 Hz virtual display).

| Measure (p50) | Swift 0.1.122 | Rust `973e7bed` |
|---|---|---|
| Warm launch to first window / visually settled | 211 / 307 ms | 154 / 154 ms |
| Cold launch (`purge` first), settled | 1344 ms | 687 ms |
| Idle CPU, one core | 0.01% | 0.46% |
| Physical footprint (Activity Monitor "Memory") | 25 MB | 78 MB |

Rust reaches a complete first window sooner, but idles at ~25–50× the CPU and
uses ~3× the memory. With `BELLO_PERF_LOG` the idle Rust app performed zero
renders while `top` showed ~63 wakeups/s: GPUI 0.2.2 runs a `CVDisplayLink` for
each visible window and invokes its frame callback every vsync. The extra memory
is window drawables (33 MB IOSurface) and Metal allocations, not app data. 
Interaction on the same long chat and loopback gateway (Swift 0.1.122 Release
build hosted with its production root view and an in-memory vault):

| Measure (p50) | Swift | Rust |
|---|---|---|
| Typing latency, idle / while streaming | 5.9 / 13.3 ms | 40.5 / 41.1 ms (p90 60 ms) |
| Transcript wheel-scroll latency | 21.0 ms | 39.3 ms |
| Find a term deep in history (n=1) | 528 ms | 260 ms |
| CPU while a 96K-character reply streams | 38% flat | 45% p50, climbing to a saturated core; **15% p50 / 19% max** after the shaped-text change below; **18% p50 / 20% max with replies drawn as Markdown** (blocks near the viewport only) |

Rust's streaming cost grew with reply length: every frame re-shaped the whole
reply as one GPUI text element, and every delta is synchronized to disk before
publication (Swift syncs when the turn settles). Rust input latency is ~2.5 frames
at 60 Hz in all cases.

Since then message text is laid out in runs of 24 lines whose shaped lines are
reused across frames while unchanged (`transcript_shaped_text.rs`), so a growing
reply re-shapes only its last run; frames are pixel-identical. Same harness, same
Mac, reply followed on screen: p50 / p90 / max CPU 31.5 / 60.8 / 82.5% before
(`9a5c960b`) and 14.7 / 17.6 / 19.1% after, now nearly flat across the 60 s
reply. What remains on the main thread is mostly ordinary rendering plus ~7% of
its time blocked on the controller lock, which the runtime held while it
synchronized each delta to disk; with the barrier sync below that is 0.9%.

## Release blockers

1. In-app provider setup works only in the experimental native-authority build:
   a signed local build saved and reread its Keychain vault without prompts,
   but locked/denied Keychain behaviour, onboarding and catalog discovery are
   unaccepted, and the ordinary build still needs a CLI profile.
2. No production tools/MCP/skills — the core of the product.
3. Migration is chats-only: no import of the vault (credentials), captures or
   settings, and no in-app import action yet (chats import from the command
   line with a backup and an undo).
4. Missing workflows users rely on: sides/forks/edits, automatic compaction,
   accounting/Inspector/dashboard/menu bar, Git/terminal, notifications.
5. No macOS interactive acceptance (focus, IME, VoiceOver, menus, windows).
6. No notarized package or update path (a local Developer ID signature works).

(CI, red at takeover, is green again since `7ece0f96`.)

## Decisions (owner, 2026-10-10)

1. **Streaming durability** (owner: "you decide a performant and good
   approach"). Each streamed delta is now written and ordered on disk with a
   write barrier (`F_BARRIERFSYNC`; full sync where a volume lacks barriers,
   `fdatasync` off macOS) instead of `F_FULLFSYNC`; the command checkpoint that
   ends a turn still syncs fully. An app crash loses nothing; a power loss can
   lose only the newest deltas of an unsettled reply, as an ordered suffix that
   replay already handles; a settled reply is fully durable, as in Swift.
   Unsynced writes were rejected: after a power loss they can leave damage in
   the middle of the journal, which replay refuses. Same streaming profile:
   the runtime worker's time in the sync fell from 31% to 10% and the UI
   thread's waits for the controller lock from 7.2% to 0.9% of its time.
2. **Idle wakeups and input latency in GPUI 0.2.2:** accepted for now; no
   patched GPUI.
3. **Swift Box JSON results** (outside the migration): fixed on BelloBox
   `dev/next` (`88e4c7f`, unreleased): results draw in a native text view,
   30/100/296 KB in 0.33/0.49/0.93 s instead of 2.3/24.6/89 s.

A Rust replacement for the next release is not realistic. What would change the
assessment: a signed native-authority build with accepted Keychain behavior, a
production tool runtime with permission parity, a tested Swift→Rust import with
rollback, and macOS interactive acceptance of the daily workflows.
