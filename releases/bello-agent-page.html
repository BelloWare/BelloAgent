Get started

Your gateway. Your project. Four steps.

Bello Agent requires your own LiteLLM gateway. Model availability, routing, reported telemetry and usage charges depend on that gateway.

  1. Install

    Open the DMG and drag Bello Agent into Applications.

  2. Connect your gateway

    Enter your LiteLLM Responses endpoint, API key and model alias. Optionally, replace the included model catalog with your own catalog URL.

  3. Choose and trust your project

    Test & Start checks the selected model with a small request before your first chat opens.

  4. Inspect turns and usage

    Click Info on a turn report to search its captured requests, responses and headers, or open the Usage Report for more.

Privacy and local storage

What Bello Agent keeps, and how.

Captured traffic is what makes every request inspectable. Adjust capture and retention in Settings.

Kept locally

  • Credentials and configuration are kept in the native Keychain vault.
  • HTTP request and response capture is on by default, with 30-day body retention, subject to your storage quota and settings.
  • New bodies are stored locally without encryption.

Masked in captures

  • Authentication headers are masked; longer request tokens keep only their final four characters.
  • Known credentials found in request bodies are replaced with SHA-256 fingerprints.
  • Bodies can still contain your prompts, files and tool data.

Figures as reported

  • Cost totals include only values the gateway reports, with coverage counts.
  • Gateway response-cache hits and provider prompt-cache tokens are shown separately.
