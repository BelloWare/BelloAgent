Bello Agent 0.1.138

  • Reasoning is sent back to the model. The reasoning a model returns with a reply (encrypted or signed) now goes back with later requests by default, also after you change the model or the connection. This starts with replies made from this version on; older replies are sent as before.
  • Settings has three choices for a connection: Send reasoning back (the default), Never send reasoning back, and Preserve native state on a fixed route. A connection you had deliberately set to portable text and tool history now sends reasoning back as well: choose "Never send reasoning back" once if you want it as it was.
  • When a provider refuses earlier reasoning, the chat asks you. The turn stops with a notice, "{model} can't use the earlier reasoning", and one button: Continue without earlier reasoning. Continue applies to that model only. Nothing is deleted, the reasoning made from then on is kept and sent, and switching back to another model still sends it everything. It asks once for a model, and your answer survives a relaunch.
  • The fixed route now works with Gemini and Claude through LiteLLM. It used to stop after the first tool call when the gateway named the model differently in its header and in its reply.
  • From one Gemini model to another, tool calls keep their signed ids.
  • The model list is there at once. A connection's last good model list is kept on disk and used straight away at launch and in the picker; it is read again in the background, and a failed read keeps the list you have.
  • A request larger than the model's window is sent whole, and the chat says so. It goes with the normal reply limit, and one line per task says how large it is, that nothing was summarized away, and that the provider may refuse it or cut the reply short. Before, such a request was sent with a reply limit of 16 tokens and the cut reply was taken as the answer.
  • Compaction works again in a small window with reasoning. In a window of about 32,000 tokens, one large tool result with its reasoning could keep a chat from ever being compacted. Now, before a request goes out over the window, your request and the newest results are kept with a summary of the rest.
  • A summary that comes back empty, or as a tool call instead of text, is asked for once more.
  • Summaries record finished work as done. A summary no longer tells the agent to start a task over; the agent goes on from where it was.
  • This version was run against real models through a LiteLLM gateway: small OpenAI, Gemini and Claude models.
  • Known: if you alternate between two models whose providers refuse each other's reasoning, the notice comes back on each round trip. "Never send reasoning back" chosen here reads as "Send" again once the connection has been saved by 0.1.137. A provider that enforces a model's declared window strictly refuses the oversized summary request once for a task; the task then goes on without compaction.
