Bello Agent 0.1.118

Changed

  • Switching a chat's connection asks when reasoning would be left behind. If earlier replies hold reasoning that only the current connection can read back, the app asks: “Earlier reasoning from A can't be sent to B. Switch anyway?” No leaves the chat exactly as it was. Yes switches it, and those replies go to the new connection as their text and tool calls. The chat's history keeps everything either way, and a switch with nothing to lose doesn't ask.
  • A switched chat keeps working on its new connection. Its saved history now moves with it, so the next message, reopen or fork uses the new connection. If the move fails, the chat stays on the old connection and keeps working there. A chat moved to another connection can't be opened by Bello Agent 0.1.117 or earlier.
  • Usage figures show at once when you switch chats. The footer's token and cost figures no longer roll from the previous chat's numbers; a figure that changes within a chat still rolls.
  • Smoother long replies and chat switches. The pauses of a quarter to half a second, seen as a long reply started streaming or when switching chats, are gone in the hour-long stress test.

Fixed

  • Changes acts only on the files you select. Discarding, deleting, staging, unstaging or committing a file whose name holds [, *, ? or a leading : could reach other files whose names matched it as a pattern. Names are now taken literally.
  • Switching a chat's connection while it was opening could leave it using the old connection. A switch and an open of the same chat now wait for each other, and a message typed during a switch is kept as a draft.
  • A queued follow-up or steering message being delivered at the moment of a crash could be lost. It now comes back after reopening, paused, and is never sent twice.
  • Closing, replacing or quitting with an unsent side conversation now keeps its whole draft, images and skills included, in the parent chat's draft. If that can't be saved, the side stays open and quit or update stops instead of losing it.
  • Nested code blocks, such as a code block in a quote inside another quote, now each show and copy their own code.
  • Very long replies finish streaming faster: matching the finished reply to what was shown takes linear time.
  • Opening a file with a very long first line no longer reads that line again for each line coloured after it.
  • MCP servers that open each response with an empty event (Streamable HTTP, 2025-11-25) now work.
  • Clearing a chat with more than 100,000 captured request chunks no longer leaves every later capture cleanup failing.
  • Closing or unloading a chat stops loading its older messages, and a retried load continues where it stopped instead of starting over.
  • Editing a question while scrolled up no longer triggers a SwiftUI update warning.
