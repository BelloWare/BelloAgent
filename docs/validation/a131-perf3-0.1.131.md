## Cause and fixes

- Each tab measured its label on every intrinsic-size query, then again in
  layout. Its size is now cached within the tab, invalidated by title changes
  or child size invalidation and keyed by backing scale. The parent still
  sums its current children, so reordering, adding and removing tabs need no
  second cache. Selection changes only the ink. An equal title skips the
  native setter as well as our invalidation; a child's size invalidation also
  invalidates its parent's size/layout. With only 24 sizing samples in the
  baseline, the remaining short array/sum does not justify another cache.
- An opened work row constructed its reasoning surface at the default
  840 pt width. Its streaming caret laid the text out there before the row
  measured its indented content. It now calls the existing `prepare(width:)`
  before `read`, using the row's known width minus the same 26 pt used for
  measurement/placement. The markdown container and DRAW-1's draw order are
  unchanged.
- `StatPill.update` invalidated its symbol and reading even for identical
  inputs; layout also redrew the reading unconditionally. It now updates the
  scope and ends an old chat's roll first, skips identical visible inputs,
  and invalidates the reading or symbol only when that part changes. Bounds
  changes still invalidate through `DrawingLayer`; appearance and backing
  scale changes update the reading's drawing environment before display.
  Repeating a reading in the same chat preserves its current roll; switching
  chats ends it even if their figures are identical. Sidebar links skip
  identical title invalidation (one setter, no search/hover changes).
- Legacy scrollers now reserve their always-visible gutter before measuring
  the first rows, including while the page is empty or fits. Overlay scrollers
  keep autohiding. A style change updates the choice. Both changes are in the
  native scroll/pane views; no paging file is needed. Long pages retain the
  same final column width and wrapping; short legacy pages keep the gutter
  too, consistent with always-visible scroll bars. The sample does not tag
  measured widths, so its 557 row-sizing samples cannot be assigned solely
  to this case; the focused before/after counts establish the duplicate work.
