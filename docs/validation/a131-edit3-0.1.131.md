## Cause and reproduction

Owner, 2026-10-23: “also, edit message should be able to use slash command”.

`WorkspaceResources.composerMoved`, `completionKey`, `chooseCompletion` and
`canSelectSkill` explicitly excluded queued edits. `QueuePanel` opened only
text, rejected added skills and sent a text-only Save. The helper's
`saveQueueEdit` preserved all old skills and identified retries by text alone.

Earlier edits already offered both skills and `LeadingCommand.reserved`:
`/side`, `/fork`, `/debug`, `/compact`. But submission redirected straight to
`sendEdit`, bypassing command resolution; a command could become literal
replacement text. Return on exact `/side` or `/fork` took another path through
the list and could execute the ordinary whole-chat action while editing.

`EditSlashCommandTests` mounts the ordinary composer and its edit banner,
types the leading slash through `ComposerTextView.keyDown`, chooses through
Return/Tab/list clicks, and submits through the menu entry and the queued
banner/earlier Resend button. `QueueEditInteractionTests` also exercises the
packaged helper, chip popover arguments/removal, restart and menu Save.

## Change

- Both edits use the normal caret-local completion list, selection checks and
  native skill tokens. Return/Tab select without submitting; Escape dismisses;
  Command-Return does not grant an unselected skill. Explicit `/skill arguments`
  resolves to a structured chip before the edit is captured.
- Queue Begin/status return recorded skill selection metadata, never expanded
  skill bodies. The composer shows the original chips and permits changes to
  selection, order and arguments. Images remain held by the helper; the ordinary
  parked draft and image-import destination keep their existing behavior.
- A changed selection is sent as optional `queue.edit.save.skills`; the helper
  freezes it through the existing resource checks (hashes, policy, dependencies,
  at most eight unique skills, argument length). Omitted skills keep the original
  frozen bodies. Empty text is valid only with a remaining skill or held image.
  A malformed/incomplete original skill reply keeps the hold and the parked
  draft, with a retry/cancel notice, rather than dropping selections.
- The helper rechecks the hold and queue position after asynchronous freezing.
  A Cancel/new edit wins over an older Save; removing another queued item cannot
  make a Save write into its former index. The existing atomic durable state
  write still publishes the replacement, receipt and released hold together;
  write failure restores the original input and hold.
- New skill-changing receipts add `inputDigest`, hashing length-prefixed text
  and ordered skill IDs/hashes/arguments. `textDigest` retains its old meaning.
  The native saved rewrite and independent submission record carry the selected
  skills, and retries/recovery compare the complete captured input. A different
  selection with the same text cannot confirm or overwrite an earlier Save.
  Legacy text-only saves/drafts keep their existing text-digest behavior.
- Newer unsaved skills stay with newer typing when an edit ends. If their
  arguments conflict with a skill in the parked draft, the complete rewrite
  is pinned and persisted as a separate restorable draft. Late argument-dialog
  and popover actions cannot mutate a queued Save already in flight.
- Earlier-edit preparation, merge/Undo steps, image imports and Send's
  `editSourcePrefix`/text checks are unchanged. Their existing regressions are
  included below. No history replay, paging, streaming or image-paste change.
