## Owner request

On 2026-10-22, during the 0.1.130 release, the owner said: "once you release the current version, please check this and try to replicate this and actually fix this. It's really, really annoying."

- **Long-chat scrolling:** with enough history loaded, tool calls are grouped ("I can see like 42 calls"); with less loaded, they become detailed rows ("which is bad"). The owner suggested about 1,000 rows so scrolling "makes much more sense". Grouping must not depend on the loaded window. On 2026-10-23 the owner chose 250-row pages in a 750-row window first, then STREAM-1 and 1,000-row pages. On 2026-10-24: "Fast first rows, then fill" — open with about 250 rows, fill the 1,000-row page, then use a 3,000-row window.
- **Editing an on-screen message:** "it still takes very long to load. Something's definitely wrong". On 2026-10-23 the owner chose to re-check an edit opened during a run at Send; later rows may have arrived, but a changed target or earlier conversation must still refuse it.
- **Floating-card opening cost** (lead, 0.1.130 soak): opening a chat beside Agents/Diff/Files cost about 10–15% more main-thread time; reply text was laid out at 840 pt, then again at the column width.
- **Finished chats, OPEN-1** (2026-10-22): "when I have multiple sessions running, and then one of them is complete, when I click on it, it actually could take a lot of time ... it doesn't make sense to me, because I mean it just finished." On 2026-10-23: a run's end counts as use for the eight kept displays.
- **Cost limit, LIMIT-1** (2026-10-22): "it got switched to $100, but I couldn't resume it. But if I switch it to like $50, it works."
- **Sidebar, SIDEBAR-1** (2026-10-22): "Flat + project filter", chosen from three mockups. Defaults kept: search all projects, keep the chip until quit, show chips only in Flat; screenshots before shipping.
- **Finding chats** (2026-10-22): the owner chose "Briefs, then Ask" (FIND-1, then FIND-2). Decisions on 2026-10-23: briefs on by default at run end, no automatic backfill, no spending cap ("no limit"), show brief usage, manual Write Brief and "write briefs for chats without one", main chats and saved sides, update at every run's end. Ask decision on 2026-10-25: "Pick a connection"; a chooser limits each Ask to one connection.
- **Images and edit commands** (2026-10-23): pasted images flash and vanish (PASTE-2); for sent images the owner chose "Thumbnails in the message" (IMG-1). "edit message should be able to use slash command" (EDIT-3); decision: keep "Wait for the edit" for commands that would leave or change the conversation.
- **Sidebar position, SIDEBAR-2** (2026-10-26): "when the left sidebar just keeps scrolling down, I think whenever there's an update happened, which feels bad because I was at the top, but then whenever a chat got updated, it seems like the chat will be hidden". Decision: "Keep selected chat visible".
- **Three 0.1.130 follow-ups** (2026-10-22): all kept as shipped. Legacy kept sides with a missing journal keep their review notice; `/side Q` while the pending side is busy or holds input refuses and keeps Q in the parent; Show/Hide Terminal stays disabled on Usage Report and Background Requests.
- **Validation scope** (2026-10-22): "they can just test whatever they mean to change. So we can reduce the test scope". Workstreams test the changed paths; the full gate stays the safety net.
- **Process:** the initial workstreams went to Claude subagents. From 2026-10-23, new tasks went to Codex gpt-6.1-sol (max), with Codex gpt-6-astra (max, read-only) reviews. On 2026-10-26, while Codex weekly usage remained, Astra implemented and reviewed new work; in-flight Sol work stayed with Sol, and the lead reviewed every diff.
- **Release cut** (2026-10-25): ship when STREAM-1, IMG-1 and Ask all land, with one full gate and soak. On 2026-10-26 the owner had the family communication limit removed and released at once ("stop all things, release this change asap!"), so that hotfix took 0.1.131; on 2026-10-27 two more sub-agent and catalog fixes took 0.1.132. Then: "now, for remaining things, please check, and release new versions". Ask's round 3 was not yet validated, so this release ships without Ask; Ask follows in its own release.
