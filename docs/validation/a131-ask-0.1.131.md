## Design as built (round 3)

**Owner, 2026-10-25: "Pick a connection."** This replaces Round 1's
interleaving choice. No connection-ordering decision remains unresolved.

- **Ask**, beside Titles & details and Full chats in the same PiKit pill.
  Typing only edits the question; Return asks. Clearing resets Titles & details,
  and no mode is persisted. The result area shows preparation, connection
  progress, Cancel, cancellation and errors. Editing the question, changing
  mode or shutting down cancels the work.
- **Connection chooser.** A custom PiKit menu pill matches the project chips
  and +N menu; it appears only when at least two connections have eligible
  chats. Names follow Settings order. A connection without a mini model is
  disabled and marked "No mini model" once its catalog is known. An unresolved
  catalog default remains selectable and resolves on Return, with no request
  while typing. A failed catalog fetch stays retryable. The selected chat's connection is the
  default when available, otherwise the first available connection with chats
  in Settings order. The choice lives only in memory, survives drafts/mode
  changes, and falls back when its connection is removed or has no eligible chats. Losing its mini
  model keeps the choice, clears the old answer and shows the needs-mini notice.
  Before an Ask, choosing only sets the connection. After results, an error or
  an in-flight request, choosing cancels and asks the same question there.
- **Bounded metadata.** A question is at most 1,000 UTF-8 bytes. Local word
  overlap (title, brief, keywords, project/topic), then recency, selects at most
  96 chats. Both word ranking and prompt preparation run off the main actor; each
  candidate is JSON-encoded once. Each title is at most
  120 bytes, brief 400, six keywords 40 each, project/topic 80 each, alongside
  the exact ID, connection and last activity. There is no transcript read for
  the model. The complete JSON prompt fits 32,000 bytes and the
  mini model's context minus output and a 3,072-token reserve, conservatively
  allowing a token per input byte. Output is at most 2,048 tokens and the
  model's own output limit; its lowest offered effort is used.
- **Own connection only.** The chosen connection is checked before reading
  a chat's title, brief or keywords. One request contains only that connection's
  main chats and saved sides and uses its own mini model and key. There is no
  partition loop, merge or interleaving. Missing mini models send nothing.
  Leases use the connection and
  generation at the metadata snapshot, and all sources are checked after
  catalog loading and again immediately before submit, after the utility
  session opens. A move/deletion before dispatch sends no candidate data to
  the old connection. A replacement request waits for cancelled helper-session
  cleanup, retaining the one-request-at-a-time rule.
- **Ranked results.** Exact candidate IDs only; unknown and duplicate IDs,
  malformed rows, empty reasons, control/bidi text and unfinished or
  malformed replies cannot become results. Fenced JSON or a sentence around
  the object is accepted; a long reason is shortened at a Character boundary
  to 239 characters and an ellipsis. Reasons are plain text, at most
  240 characters, one drawn line with full accessible text. At most 12 results.
  The summary names the connection, e.g. "2 relevant chats in Studio · 2 checked".
- **Publish, then confirm.** Validated rankings publish before any index read.
  Only the top eight get local full-text checks, one journal at a time. An
  independent reader reuses a committed library snapshot at the chat's path,
  even when its revision is older. With no library entry, the fallback reads at
  most 256 KiB and 512 complete records from the newest part of that journal,
  in memory on a detached task. It follows the newest parent chain, stops at
  branch/compaction boundaries, and conservatively skips a tail containing an
  unresolved visibility or presentation update. Oversize and partial records
  give no excerpt. It never awaits `reconcileNow()` or the library writer, and
  creates no private index, cache, file, lease or sweep. Crash, force quit and
  quit leave no transcript copy; another instance has nothing to delete.
  Each excerpt publishes as soon as its journal is checked. Two snippet lines
  stay reserved, including no-hit results. Cancel is an accessible PiKit xmark
  on the status line's trailing side: hiding it leaves no band and moves no
  result. A later Ask, Cancel, mode or connection change drops enrichment. Matching excerpts stay local. A
  semantic match without a literal excerpt keeps its reason and "No matching
  excerpt available." The ordinary chat-open/snippet-reveal path is retained.
- **Existing choices kept.** Search spans every project; the archive switch
  applies. Main chats and saved sides are candidates, with title/details
  fallback when no brief is available. Unkept sides, sub-agents, utility and
  pending chats are excluded. Briefs off uses only titles/details; changing
  the brief setting cancels a preparation and clears results based on the
  earlier setting. No spending cap.
- **Accounting.** Each Ask is one `Ask chats` background request, purpose
  `chat-ask`, with its own record, journal, outcome, captured request and Usage
  accounting. No tools, project instructions or compaction. Background requests
  has an Ask chats filter. The request's source link is its first candidate,
  on the same connection.

## Round 3 review fixes (2026-10-26)

- **A, uncached mini defaults:** availability distinguishes an unloaded/failed
  catalog from a known list with no mini model. Unresolved choices can be
  selected; `run` loads only that choice's catalog and revalidates its model
  and source leases before sending. The fixture catalog uses an injected
  generated descriptor and the ranking still uses the loopback mini gateway.
- **B, empty choice:** `connectionsChanged()` falls back when the chosen
  connection no longer has eligible chats. Chat changes schedule that method
  after publication. Deleting or moving the last chat clears the old answer,
  resolves the default and sends nothing until Return or an explicit choice.
- **C + E, interrupted/unbounded private indexes:** the private index is gone.
  A saved library snapshot is used without reconciling; a cold check is bounded
  as above and owns no on-disk text. No garbage collector can race a second
  instance. The model revalidates the chat/connection before publishing the
  excerpt and removes deleted chats' retained hits.
- **D, fenced rankings:** the parser takes the first `{` through the last `}`,
  as briefs/webhooks do, within the existing 64,000-byte reply bound. The prompt
  adds their exact no-Markdown/no-fences/no-extra-text instruction.
- **P3s:** one encoding per candidate, prompt work off the main actor; long
  reasons shortened; the connection getter is read-only (only the change
  handler resets a vanished/empty choice); six-point label padding with
  "Details" at 200 pt and the full title as tooltip/VoiceOver label; trailing
  Cancel removes the reserved blank band. Native Tab/AX behavior and per-row
  snippet reservations from round 2b are retained and tested.

The owner’s **"Pick a connection"** decision is unchanged. Conservative choices
are automatic fallback without an automatic request, no conversation-model
fallback, and no guessed excerpt when a cold bounded tail cannot establish
visible text. Existing library excerpts can be older than the current journal;
Ask ranking is metadata-based and the snippet is local supporting evidence,
not a claim to have re-read the whole chat. No owner decision is outstanding.

## Round 2 reproduction and conservative choices (historical)

Astra P2's cause was the awaited `reconcileNow()` before assigning `matches`:
it joined an existing pass and could start another over the whole library.
A cold index held on a slow, unrelated connection's journal reproduced the
blocked answer. The regression gates that journal independently of the top
results. Before the fix, the rankings timed out; after, both rows and their
snippet placeholders appear while that journal is still held, and each result's
snippet fills independently with identical row positions. This is deterministic
ordering evidence, not a Debug speed benchmark.

The chooser-removal regression also reproduced a stale answer when the sidebar
resolved its fallback label before the queued Settings observer. Resolving a
removed choice now cancels and clears that answer before selecting the default.

Conservative choices: no automatic request on Settings changes, removal,
typing or mini-model loss; no conversation-model fallback; no-hit semantic
results retain their reason and reserved excerpt space. Fixture messages now
derive from each chat's own title/brief (or explicit text), so the gallery's
different chats have different, relevant excerpts. No helper/wire contract
changed in Round 2.

Engineering limits are explicit in the result caption: for example, 96
candidates checked of 10,000 chats. Ask is not an exhaustive semantic scan
when the local shortlist or context budget excludes chats.
