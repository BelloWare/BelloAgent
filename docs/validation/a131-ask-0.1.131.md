## Request and design

The owner chose **Briefs, then Ask**. FIND-1 is merged; FIND-2 was absent:
sidebar search had two modes and Return opened its first local result.

- **Ask**, beside Titles & details and Full chats in the same PiKit pill.
  Typing only edits the question; Return asks. Clearing resets Titles & details,
  and no mode is persisted. The result area shows preparation, connection
  progress, text checking, Cancel, cancellation, failures and skipped connections.
  Editing the question, changing mode or shutting down cancels the work.
- **Bounded metadata.** A question is at most 1,000 UTF-8 bytes. Local word
  overlap (title, brief, keywords, project/topic), then recency, selects at most
  96 chats. The word ranking runs off the main actor. Each title is at most
  120 bytes, brief 400, six keywords 40 each, project/topic 80 each, alongside
  the exact ID, connection and last activity. There is no transcript read for
  the model. Each partition's complete JSON prompt fits 32,000 bytes and the
  mini model's context minus output and a 3,072-token reserve, conservatively
  allowing a token per input byte. Output is at most 2,048 tokens and the
  model's own output limit; its lowest offered effort is used.
- **Own connection only.** Candidates are partitioned by connection, and each
  partition goes to that connection's mini model and key, one request at a
  time. A connection without a mini model is skipped, with a notice, without
  falling back to its conversation model. Leases use the connection and
  generation at the metadata snapshot, and all sources are checked after
  catalog loading and again immediately before submit, after the utility
  session opens. A move/deletion before dispatch sends no candidate data to
  the old connection. Other partitions can still succeed.
- **Ranked results.** Exact candidate IDs only; unknown and duplicate IDs,
  malformed rows, empty/oversize reasons, control/bidi text and unfinished or
  malformed replies cannot become results. Reasons are plain text, at most
  240 characters, one drawn line with full accessible text. Rank lists are
  interleaved by rank locally, with no extra model merge. At most 12 results.
  The index checks only the top eight IDs, first for the question, then up to
  eight meaningful question terms. Matching excerpts stay local. A semantic
  match without a literal excerpt keeps its reason. The existing chat-open
  and snippet-reveal path opens either the row or its reason.
- **Existing choices kept.** Search spans every project; the archive switch
  applies. Main chats and saved sides are candidates, with title/details
  fallback when no brief is available. Unkept sides, sub-agents, utility and
  pending chats are excluded. Briefs off uses only titles/details; changing
  the brief setting cancels a preparation and clears results based on the
  earlier setting. No spending cap.
- **Accounting.** Each partition is an `Ask chats` background request, purpose
  `chat-ask`, with its own record, journal, outcome, captured request and Usage
  accounting. No tools, project instructions or compaction. Background requests
  has an Ask chats filter. The request's source link is its first candidate,
  on the same connection.

## Decisions

The owner's existing choices (Return to ask, temporary mode, each connection's
own mini model, no spending cap, every-project search) are implemented. No
privacy simplification or decision is deferred.

**Needs owner decision — ordering equal ranks from different connections.**
The conservative implemented choice is (a) interleave each connection's first
match, then each second match, with connections ordered by their first local
candidate. Alternatives: (b) newest activity breaks equal ranks; (c) a
connection chooser, ranking only that connection. Model-provided scores are
not compared across connections, and no connection sees another's candidates.

Engineering limits are explicit in the result caption: for example, 96
candidates checked of 10,000 chats. Ask is not an exhaustive semantic scan
when the local shortlist or context budget excludes chats.

The first full path caught two real integration gaps: `WorkspaceHosts.open`
allowed only the earlier four utility kinds, so Ask reached the helper as a
conversation (`turn` purpose and generic agent instructions); adding `.ask`
passes it through the helper's existing utility boundary. Leases were also
being captured after local prefiltering, so a chat moved during that await
could send the old metadata through the old connection. Leases now retain
snapshot generations; the regression observed one request before, zero after.
Turning briefs off during preparation originally still sent the earlier
brief; the search's setting observer now cancels it before dispatch. The saved
side regression also showed that normalizing a missing topic was insufficient:
normal group filtering with an empty query deliberately omits family children.
Ask now builds each ranked row directly with its own ordinary row state, so a
saved side and missing topic cannot hide a ranked result.

Two initial compile diagnostics about a local validation function's actor /
sendable conversion are retained in `compile-initial.log` and
`compile-validator.log`; an explicitly typed main-actor sendable closure
resolved them. They are build diagnostics, not test counts.
